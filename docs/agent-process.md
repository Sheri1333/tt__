
## Декомпозиция

Порядок выбран так, чтобы каждый следующий слой опирался на уже проверенный:

1. **Контракт данных** — `shared/types.ts` по трём конфигам сразу (v1, v2, v3), чтобы схема заранее покрывала вторую итерацию.
2. **Чистый движок** `shared/engine.ts` — условия, видимость, прогресс, валидация, результат, бакетинг. Без I/O, поэтому тестируется изолированно и переиспользуется клиентом, сервером и генератором.
3. **Backend** по сервисам с узкими обязанностями: `versions` → `sessions` → `events` → `analytics` → `app` (HTTP-обвязка).
4. **Тесты на требования 7.1** — написаны и прогнаны до UI; UI строился уже на проверенном API.
5. **Frontend**: рендерер шагов, трекер, внутренние страницы.
6. **Генератор** — одновременно инструмент наполнения и независимая проверка: он ведёт собственную «истину» и сверяет с ней dashboard.
7. **Ручной QA в браузере** (встроенный браузер Claude Code) и документация.

Параллельности по агентам не было: задача связная (общий движок и контракт событий), и последовательная работа с проверкой на каждом шаге оказалась дешевле, чем синхронизация нескольких агентов по общим типам. Естественные точки распараллеливания, если бы команда агентов понадобилась: (a) frontend против зафиксированного API и `shared/types.ts`, (b) генератор против того же API, (c) отдельный агент-ревьюер на diff с чек-листом инвариантов из README.

## Как проверялся результат

| Уровень | Что | Что нашлось / подтвердилось |
|---|---|---|
| Типы | `tsc --noEmit` по всему репозиторию (shared + server + client + scripts + tests) | чисто |
| Unit/API | 26 тестов vitest + supertest на in-memory SQLite | все требования 7.1 покрыты; тесты зафиксировали причины отказа для каждого типа битого события |
| Сквозная сверка | `npm run scenario` и `npm run generate`: сравнение приращений dashboard с «истиной» генератора при сотнях дублей, повторных пачек и перестановок | совпадение по всем версиям × вариантам |
| Ручной QA | браузер: валидация пустого/вне диапазона ввода, ветка `hybrid` (7 → 8 шагов), refresh и повторное открытие, Back в UI и через историю браузера (ответ сохраняется), результат `meeting_heavy` при 18 часах встреч, CTA раскрывает рекомендации, события доходят, состояние CTA сохраняется после refresh | работает |
| Ревью инвариантов | перечитывание README против кода | найдено расхождение: утверждение «отвалы + дошедшие = Started» не выполнялось для сессии только с `session_started` (probe-сессия сценария давала 99% на intro). Исправлено правилом «начатая сессия ⇒ шаг 0 достигнут», добавлен тест |
